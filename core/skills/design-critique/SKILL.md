# Design critique

Load the project's UI and product hooks. Establish the artifact, user goal, constraints, and a short definition of success. Screenshots are visual evidence, not proof of system behavior.

Evaluate product logic, flow, hierarchy, project consistency, mobile composition, accessibility, typography, spacing, color, surfaces, and polish—in that order. Identify the smallest root causes with the greatest impact. Use `CRITICAL`, `IMPORTANT`, and `POLISH` only when genuine.

Question contextless cards, excessive rounding or whitespace, decorative effects without meaning, duplicated actions, equal emphasis on unequal tasks, arbitrary inconsistency, compressed-desktop mobile layouts, and polish masking product problems. These patterns are not blanket prohibitions.

Converge on one coherent correction; offer another only for a real structural tradeoff.
